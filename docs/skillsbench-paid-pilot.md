## Acceptance

1. Preparation is keyless and binds one task, exact model, image, source closure,
   qualification evidence, skill/support bytes, prompt, finite runtime and gateway
   policy. Drift or wrong/expired approval fails before credentials or containers.
2. Only the gateway receives the selected provider key and outbound network.
   DSH receives one task's visible data and frozen skills; it cannot see private
   oracle/verifier files, the checkout, the ledger or a provider key. Files are
   graded in a separate offline container after candidate termination.
3. A run publishes an exclusive manifest and receipt binding actual output
   inventories, verifier evidence, execution status and gateway accounting.
   Setup/timeout errors never become development business failures. Reusing a
   batch never authorizes a retry.
4. A passing development baseline means no change needed. A failed business
   outcome needs causal review before proposing. Comparisons require the same
   task/model/runtime/context, different selected skill bytes, valid immutable
   evidence and a strictly positive outcome delta; never authorize promotion.
5. No historical cap or reservation is edited. An approved cap extension is a
   zero-spend record appended under the existing ledger lock and hash chain.
   Preparation binds old/new caps, provider, budget, current total, sequence and
   head. Stale heads or absent exact approval fail. Reservations use the cap
   effective at their sequence; old readers fail closed after extension.

## Scientific boundary

The optional pilot-local `--harness-profile lean` is defined in the linked pilot
README. Standard remains the default. Profile selection changes the rendered
patch and therefore approval and comparison context; a cross-profile result is
not a skill-only gain. Rehearsal and new live receipts validate the native tool
catalog, while historical receipts remain unchanged. No budget or grader rule is
relaxed by choosing the lean profile.

Development is `threejs-to-obj`; transfer is `threejs-structure-parser`. Freeze
the candidate before any paid transfer observation. Oracle/no-op qualification
does not expose transfer outcomes from an evaluated model to the proposer.
The common support skill directory stays fixed; treatment replaces only
obj-exporter/SKILL.md. Public source availability is not a private benchmark claim.
No official SkillsBench score, broad reliability or causal improvement follows
from one pair of trials. Existing tau task enrollment remains strict and separate.

The whole-object verifier checks vertices and presence of faces, not complete
topology. Upstream requirements and verifiers are not modified to create a
failure or rescue a candidate. A verifier ambiguity stops adaptation rather than
turning the hidden answer into a skill instruction.
